PASS 1 — EVIDENCE FORM GENERATION (schemaVersion 3).

Generate a tailored evidence-collection form for a user returning/selling a used item.
Ask the fewest, highest-signal things needed to grade THIS product and verify the reason.

PRODUCT-SPECIFIC INSTRUCTIONS COME FIRST (if a "PRODUCT-SPECIFIC INSTRUCTIONS" section
is present, obey it literally):
  • Any field / capture it names (e.g. "request a video", "TOP VIEW compulsory") MUST
    appear with required=true, using its exact wording, label, and media type.
  • You still freely design the REST of the form (steps, extra helpful fields, ordering,
    standard category checks). The instructions only mandate what they explicitly list.
  • If it says "pass all" / "don't verify" → set every field required=false with
    permissive validation_criteria (e.g. "Any photo of the item is acceptable.").

INPUT CONTEXT:
- Reason: {reason}
- Category: {category}
- Product listing data: {listing_data}
- Customer trust tier: {trust_tier}
- Item value: {item_value}
{image_hints_section}

ATTACHED IMAGES (may be empty): reference photos of the catalog product, then any
clarifying photos the user already uploaded. Use references to make the form specific to
THIS product. Fall back to category-level reasoning if they're empty.

OUTPUT — a Form_Schema JSON object with EXACTLY this shape:
{{
  "title": "<short form title>",
  "schemaVersion": 3,
  "category": "{category}",
  "steps": [
    {{
      "id": "<snake_case_step_id>",
      "title": "<short step name>",
      "purpose": "<one line>",
      "fields": [
        {{
          "id": "<snake_case_field_id>",
          "label": "<human readable label>",
          "type": "photo | video | text | boolean | select",
          "required": true | false,
          "capture_mode": "video | photo | text",
          "guidance": "<what to capture / what to pan across>",
          "options": ["<only for type=select>"],
          "aspects": [
            {{
              "id": "<snake_case_aspect_id>",
              "kind": "angle | region | label | functional",
              "verifiability": "photo | ocr | none",
              "importance": "critical | standard | minor",
              "detail_level": "high | normal",
              "expected_subject": "<what must be shown>",
              "required_views": ["<precise view>", "<precise view>"],
              "validation_criteria": "<what makes the evidence acceptable>",
              "satisfied": false
            }}
          ]
        }}
      ]
    }}
  ],
  "photo_guidance": ["<short tip>", "<short tip>"]
}}

RULES:
- Every photo/video field carries an "aspects" array. A text field carries one aspect
  with verifiability=none and no media.
- Order steps: (1) identity/overall condition, (2) category checks, (3) reason-specific
  defect. De-duplicate — ask each distinct thing once. Cap at 8 photo/video fields.
- required=true ONLY for genuinely blocking fields (the claimed defect, or an identity
  shot if no other photo exists) — at most 1-2 per form. Everything else required=false.
- Aspects: for kind=angle/region, fill required_views with PRECISE terms (never "sides" —
  name each edge/region). Prefer ONE video over many angles; state exactly what to pan
  across. kind=label → verifiability=ocr. Claims a camera can't confirm
  (internal fault, smell, fit) → verifiability=none, collect as text, never request
  media to "prove" them.
- importance: reason-related → critical; standard checks → standard; nice-to-have → minor.
  detail_level: defect/texture aspects → high; else normal.
- If a clarifying photo already shows an aspect, set "satisfied": true and don't re-request.
- Fit/size reasons: treat the fit claim as ACCEPTED; emit no aspect to verify it, but
  still emit normal condition aspects.
- Scale by context: high value OR low trust → more evidence, stricter criteria; low value
  OR high trust → less, lenient; "unknown" → neutral. Always cap at 8 photo/video fields.

Return ONLY the JSON object. No prose, no markdown, no code fences.
