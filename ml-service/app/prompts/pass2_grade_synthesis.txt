PASS 2 — GRADE SYNTHESIS

You are given a structured Analysis_Summary assembled from Evidence Inspector
fragments. The summary is organized BY FIELD. Each field's entry uses ONE of two
shapes (you must handle both):

  • v2.35 (field-level fragment, preferred): the inspector judged ALL photos for
    that field as a set in one call. Carries:
      image_urls            – the photos in the set
      per_photo[]           – per-photo descriptive notes ({{role, usable, note}})
      missing_views         – named views the user still needs to add (if any)
      observations          – cross-set neutral findings
      condition_signals     – described wear/damage (NOT graded)
      ocr_text_per_photo    – any legible text per photo
      inspector_status      – "ok" | "unavailable" | …

  • v2.34 (per-photo fragments, legacy): the field's entry has a `photos[]` list
    where each photo carries clarity, subject_match, identity_match, observations,
    condition_signals, ocr_text, inspector_status, preflight.

You do NOT receive raw images — reason only from the summary text below. You are
the ONLY step that assigns a grade.

ANALYSIS SUMMARY:
{analysis_summary}

Using the grading rubric, synthesize a single canonical Grade JSON with this exact shape:
{{
  "grade": "A | B | C | D",
  "qualityScore": <integer 0-100>,
  "confidence": "high | medium | low",
  "defects": [
    {{ "type": "<string>", "severity": "minor | moderate | major",
       "location": "<field name or place on item>", "description": "<string>" }}
  ],
  "missingEvidence": ["<field name>"],
  "returnClaimVerified": <true | false>,
  "estimatedResalePct": <number 0.0-1.0>,
  "routingHint": "resell | refurbish | donate | liquidate",
  "rationale": "<concise justification grounded in the summary>"
}}

RULES:
- Reason over each field's evidence. Reference findings by the named field they
  came from (e.g. "sole_photo shows heavy tread wear") and put that field name in
  each defect's "location".
- The fragments DESCRIBE; YOU assign each defect's severity (minor/moderate/major)
  and the overall grade. Do not expect severities in the input.
- For any required field that has no usable evidence — including a v2.35 field
  fragment with non-empty `missing_views`, or a v2.34 per-photo fragment with
  identity/subject mismatch reported, or no fragment at all — list that field in
  missingEvidence and set confidence to medium or low (never high).
- If "warnings" includes "identity_mismatch_reported", treat the item identity as
  unverified: reflect it in the rationale, do not grade higher than C on identity doubt.
- If a hard or soft fraud signal is present in "fraud", reflect it in the rationale and grade.
- grade, confidence, and routingHint MUST be one of the allowed enum values exactly.
- Return ONLY the JSON object, no surrounding text, no code fences.
