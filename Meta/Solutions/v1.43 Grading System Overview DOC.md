# AI Grading System — Technical Documentation

## Overview

The grading system uses a **hybrid AI pipeline** to replace manual product inspection.
Specialized tools handle individual tasks cheaply and fast. A multimodal LLM
(via Amazon Bedrock) only runs at the end — receiving a structured summary, not raw images — to synthesize the final grade.

**Why hybrid?** Sending everything to one LLM is expensive, slow, and unreliable.
Specialized tools are faster, free or near-free, and better at their specific jobs.

---

## Full Pipeline Flow

```
[1] User opens return URL
         │
         ▼
[2] User submits: return reason (text) + optional initial images
         │
         ▼
[3] FRAUD CHECK (before any processing)
    • imagehash    — perceptual hash vs known catalog images (stock photo check)
    • Pillow/EXIF  — metadata check (real photos carry camera data; stock images don't)
    • AWS Rekognition — open-web reverse image match
    → If flagged: reject submission early, save all downstream costs.
         │
         ▼
[4] BEDROCK PASS 1 — Form Generator
    Inputs:  user reason + initial images + base prompt
             + category prompt + product listing data
    Model:   Amazon Nova Pro (multimodal) or Claude 3.5 Sonnet on Bedrock
    Output:  JSON form schema → dynamically rendered React page

    > Pass 1 caching: key = hash(product_id + normalized_return_reason).
    > Identical product + reason reuses cached schema — no repeat LLM calls.
         │
         ▼
[5] Progressive form shown instantly (generic fields) while Pass 1 runs.
    Targeted AI fields replace generic ones on arrival (~3-5s).
         │
         ▼
[6] Per-photo validation as user uploads each image (real-time):
    • OpenCV       — blur + lighting check
    • CLIP         — subject match ("does this show a tie collar?")
    → Instant feedback if photo is wrong before form submission.
         │
         ▼
[7] User submits completed form
         │
         ▼
[8] SPECIALIZED ANALYSIS (runs in parallel, all fast/cheap)
    ┌─────────────────────────────────────────────────────┐
    │ OpenCV          Dominant color extraction           │
    │                 Visual histogram vs listing photo   │
    ├─────────────────────────────────────────────────────┤
    │ CLIP            Overall visual similarity score     │
    │                 vs original listing photos          │
    ├─────────────────────────────────────────────────────┤
    │ AWS Rekognition Defect/damage label detection       │
    │ (Label Detection API — no training needed)          │
    ├─────────────────────────────────────────────────────┤
    │ AWS Textract    Read serial numbers, labels, tags   │
    │                 from product photos                 │
    └─────────────────────────────────────────────────────┘
    All outputs → assembled into one structured JSON summary
         │
         ▼
[9] BEDROCK PASS 2 — Grade Synthesizer
    Input:   structured JSON summary (NOT raw images)
    Model:   Amazon Nova Pro or Claude 3.5 Sonnet on Bedrock
    Output:  final grade JSON
         │
         ▼
[10] Grade stored in MongoDB
     → if confidence: "low" or missing_evidence non-empty → flagged for human review
     → else Smart Routing engine triggered
```

## Prompting Architecture

### Base Prompt
Injected into both Pass 1 and Pass 2. Category-agnostic grading rules.

```
You are a product condition inspector for a second-life commerce platform.

Grading rubric:
  Grade A (Like New):   No visible defects. Original condition.
  Grade B (Good):       Minor cosmetic wear. Fully functional.
  Grade C (Fair):       Visible defects. Functional but imperfect.
  Grade D (For Parts):  Significant damage. May be non-functional.

Return ONLY valid JSON matching the schema provided. No prose outside JSON.
```

### Category Prompt
Product-type-specific overlay. One prompt file per category, injected alongside base prompt.

```
// Example: Apparel
Focus on:        fabric integrity, stitching, collar, zipper, color vs listing, stains, pilling.
Ignore:          crease lines (expected in shipped apparel).
High-risk zones: collar, cuffs, underarm area.
```

### Pass 1 — Form Generation Prompt
```
Given:
- Return reason: "{user_reason}"
- Product: "{listing_title}" — "{listing_description}"
- Category rules: {category_prompt}

Generate a JSON form schema with the minimum specific fields needed
to verify this exact return claim. Do not request information
already visible in the attached listing photos.
```

### Pass 2 — Grade Synthesis Prompt
```
You are given a structured analysis summary produced by specialized vision tools.
Using this data and the grading rubric, produce the final condition grade.
You do not have access to raw images — reason only from the data provided.
If any field shows insufficient_evidence, reflect this in your confidence score.
```

## Implementation Notes

- **All specialized tools** run inside one Python FastAPI microservice. Express calls it via HTTP.
- **Images** uploaded to AWS S3. All tools receive S3 URLs — nothing stored locally.
- **Pass 1 and Pass 2** call Amazon Bedrock via the AWS SDK (boto3 in Python or `@aws-sdk/client-bedrock-runtime` in Node).
- **Parallel execution in Step 8**: run OpenCV + CLIP + Rekognition + Textract concurrently using `asyncio.gather()` in FastAPI. Assemble results before calling Pass 2.
- **Grade versioning**: store full evidence bundle (S3 image URLs + form schema + analysis summary + prompts) with each grade record in MongoDB for dispute resolution and future retraining.

## Model & Tool Acquisition Guide

### 1. OpenCV
**What it does here:** Blur detection, lighting check, color extraction.
**Type:** Classical computer vision library — no AI, no training, no API key.

**Setup:**
```bash
pip install opencv-python numpy
```
That's it. Import and use immediately. Runs on any machine, zero cost.

**Time to integrate:** 1–2 hours.

---

### 2. CLIP
**What it does here:** Subject verification ("does this photo show a collar?"),
visual similarity score between submitted photos and listing photos.
**Type:** Open-source AI model from OpenAI. Runs locally — no API key, no cost.

**Setup:**
```bash
pip install torch transformers Pillow
```

```python
from transformers import CLIPProcessor, CLIPModel

model = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")
# Model (~600MB) downloads automatically from Hugging Face on first run.
# Subsequent runs load from local cache — no repeated download.
```

**Where models are stored:** Hugging Face Model Hub (huggingface.co) — a free
public library of thousands of AI models. `from_pretrained("...")` downloads and
caches the model automatically.

**Does it need training?** No. CLIP is pre-trained on 400M image-text pairs.
It works zero-shot — you just give it an image and a text description and it
returns a similarity score. No fine-tuning needed for your use case.

**Hardware:** Runs on CPU (slower, ~1–2s per image) or GPU (fast, ~0.1s).
For a hackathon demo, CPU is fine.

**Time to integrate:** 2–3 hours.

---

### 3. AWS Rekognition
**What it does here:**
- **Label Detection** (built-in, no training): detects general objects/concepts
  in images ("scratch", "damage", "worn fabric", "stain"). Free tier: 5,000
  images/month for 12 months.
- **Image Properties / Web Detection**: checks if a photo exists on the web
  (fraud check).

No training needed. Works across any product category out of the box — exactly
what you need when you can't pre-train per product.

**Setup:**
```bash
pip install boto3
aws configure  # enter your AWS access key + secret key
```

```python
import boto3
client = boto3.client('rekognition', region_name='us-east-1')

response = client.detect_labels(
    Image={'S3Object': {'Bucket': 'your-bucket', 'Name': 'photo.jpg'}},
    MaxLabels=20,
    MinConfidence=70
)
# Returns labels like: "Scratch", "Damage", "Stain", "Worn", "Torn" with confidence scores
```

**Time to integrate:** 1 hour.

---

### 4. AWS Textract
**What it does here:** Reads text from product photos — serial numbers,
brand labels, care tags, warranty stickers.
**Type:** AWS managed OCR service. No setup, no training, just an API call.
Free tier: 1,000 pages/month for 3 months.

**Setup:** Same boto3 as Rekognition. No extra install needed.

```python
client = boto3.client('textract', region_name='us-east-1')

response = client.detect_document_text(
    Document={'S3Object': {'Bucket': 'your-bucket', 'Name': 'label_photo.jpg'}}
)

# Extract all text blocks
text = " ".join([b['Text'] for b in response['Blocks'] if b['BlockType'] == 'LINE'])
```

**Time to integrate:** 30 minutes.

### 5. imagehash + Pillow (Fraud Detection)
**What it does here:** Detects if a submitted photo is a copied catalog/stock image.
**Type:** Python libraries. No AI, no training, no API key.

```bash
pip install imagehash Pillow exifread
```

**How perceptual hashing works (simply):** Converts any image into a short
"fingerprint" (a hash). Two identical or near-identical images produce near-identical
hashes. You pre-compute hashes of all known catalog/stock images and store them.
When a user uploads a photo, compute its hash and compare — if the Hamming distance
is below a threshold (~10), it's a match (likely copied).

**How EXIF check works:** Real camera photos contain metadata baked in by the
camera — make, model, shutter speed, GPS, timestamp. Stock images downloaded from
the internet typically have this stripped. Check for presence of camera metadata
as a fraud signal (weak alone, strong combined with hash check).

**Time to integrate:** 1 hour.

---

### 6. Amazon Bedrock (MLLM — Pass 1 and Pass 2)
**What it does here:** Pass 1 (form generation) and Pass 2 (grade synthesis).
**Type:** AWS managed API for foundation models. Pay per token.

**Which model to use:**
- **Amazon Nova Pro** — Amazon's own multimodal model (text + images).
  Best choice for an Amazon hackathon — judges will notice.
  Pricing: ~$0.0008/1K input tokens, ~$0.0032/1K output tokens (very cheap).
- **Claude 3.5 Sonnet on Bedrock** — Strongest reasoning, also multimodal.
  Pricing: ~$0.003/1K input tokens, ~$0.015/1K output tokens.
- **Llama 3.2 Vision on Bedrock** — Open-source option, cheapest.

For Pass 2, since you're sending structured JSON (not raw images), even a
text-only model works. Nova Lite or Claude Haiku would be sufficient and cheaper.

**Setup:**
1. AWS Console → Bedrock → Model Access → request access to Nova Pro + Claude.
   (Approval is instant for most models.)
2. Install SDK:
```bash
pip install boto3
# or in Node:
npm install @aws-sdk/client-bedrock-runtime
```

```python
import boto3, json

client = boto3.client('bedrock-runtime', region_name='us-east-1')

response = client.converse(
    modelId='amazon.nova-pro-v1:0',
    messages=[{
        'role': 'user',
        'content': [
            {
                'image': {
                    'format': 'jpeg',
                    'source': {'bytes': image_bytes}  # or S3 reference
                }
            },
            { 'text': 'Your prompt here...' }
        ]
    }],
    inferenceConfig={ 'maxTokens': 1000, 'temperature': 0 }
)
```

**Hackathon credits:** Amazon hackathons typically provide AWS credits.
Apply them to your account at console.aws.amazon.com → Billing → Credits.
Bedrock usage at this scale will cost well under $5 total for the entire event.

**Time to integrate:** 2–3 hours (most time is reading Bedrock docs and
getting model access approved — do this on Day 1).

### 7. AWS S3 (Image Storage)
**What it does here:** Central store for all uploaded product photos.
Every tool receives an S3 URL — nothing stored locally.
Free tier: 5GB storage + 20,000 GET requests/month for 12 months.

**Setup:**
```bash
pip install boto3
# or: npm install @aws-sdk/client-s3
```

```python
import boto3
s3 = boto3.client('s3')
s3.upload_fileobj(file_obj, 'your-bucket-name', 'uploads/photo.jpg')
url = f"https://your-bucket-name.s3.amazonaws.com/uploads/photo.jpg"
```

**Time to integrate:** 30 minutes.
